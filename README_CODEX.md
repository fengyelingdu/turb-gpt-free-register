# Turb GPT Free Register：新手使用说明（Codex 整理版）

这是一套在你自己电脑上运行的 **ChatGPT / OpenAI 账号注册与管理工具**。你提供邮箱、可用网络及所选服务的配置，它负责执行注册步骤、获取验证码、保存账号信息；需要时，还可以继续完成 Codex OAuth 授权。

本说明依据当前仓库代码整理，独立于原版 `README.md`，重点回答：**它做什么、需要准备什么、第一次怎么运行、成功后去哪里看结果。** 文中的操作指南经过代码核对，实际注册结果仍取决于服务端页面、邮箱和网络状况。

> 第一次使用，按第 3 节完成一个账号的试跑即可。邮箱池、批量任务、Codex 授权都可以之后再配置。

## 1. 先弄清楚这个项目做什么

可以把它理解成一个带网页控制台的注册助手：

```text
准备邮箱和网络
      ↓
打开本地网页控制台，提交注册任务
      ↓
程序访问注册页面，填写邮箱、密码及资料，完成邮箱验证
      ↓
取得登录凭证，保存账号到本机数据库
      ↓
可选：继续做 Codex 授权，或之后单独补跑
```

它主要提供这些功能：

| 功能 | 用普通话解释 |
| --- | --- |
| 注册账号 | 用浏览器自动操作或直接发送网络请求，完成账号注册流程 |
| 邮箱与验证码管理 | 从你准备的邮箱中取一个地址，并自动收验证码；也支持手动填验证码 |
| 账号管理 | 查看账号、复制登录凭据、导出数据、写备注、归档、查活、换绑邮箱 |
| Codex OAuth 授权 | 为已有账号继续执行授权流程，保存授权凭证或外部服务的回执 |
| 批量任务 | 一次提交多个任务，查看进度、失败原因和日志 |
| 可选扩展 | 2FA、套餐查询、试用链接、Codex Agent、CPA / sub2api 对接等 |

**注册成功、Codex 授权成功、获得付费套餐是三件不同的事。** 本项目不会因为名字里有 “Free” 就自动提供 Plus、无限额度、免费邮箱或免费短信。源码采用 MIT 许可证；邮箱、代理、云浏览器、短信等第三方服务可能收费，具体取决于你选择的服务。

如果你的目的只是日常聊天或使用编程工具，通常直接在相应官方产品中注册、登录即可；这套项目主要用于运行和管理自动化流程。使用时应遵守相关服务的条款。

## 2. 几个经常出现的词

| 名词 | 在这个项目里是什么意思 |
| --- | --- |
| WebUI | 用浏览器打开的本地管理页面，不需要自己写代码 |
| CLI | 在 PowerShell / 终端中输入命令运行程序 |
| 驱动 | 程序执行注册或授权的方式，例如控制本地浏览器、云端浏览器 |
| OTP | 邮件或短信里的一次性验证码，邮箱验证码通常是 6 位数字 |
| 邮箱池 | 提前导入、等待程序使用的一批邮箱及收信凭据 |
| 代理 | 程序访问网络时使用的中转地址；本项目不会替你安装或启动代理服务 |
| Token / AT | 代表账号登录状态的凭证，需要像密码一样保管；会过期，不等同于通用 API Key |
| OAuth | 登录账号并完成授权的流程；完成注册后，可能还需要单独做这一步 |
| 线程数 | 同时执行的任务数量；数量为 10、线程为 2，表示共做 10 个任务，同时最多跑 2 个 |
| 2FA / TOTP | 额外的动态口令验证；密钥用于在验证器里生成验证码 |

## 3. 第一次使用：先跑通一个账号

本节采用 **CloakBrowser + 手动收邮件 + 一个任务**。这样不需要先配置 Roxy、邮箱供应商 API、CPA 或短信平台。CloakBrowser 仍需要下载并运行适合你系统的浏览器组件。

### 3.1 准备什么

| 需要的东西 | 用途 |
| --- | --- |
| 项目源码 | 下载并解压，或使用 Git 获取；根目录应能看到 `web.py`、`main.py`、`requirements.txt` |
| Python 3.10 或以上 | 运行程序；初次安装可以选 Python 3.11 / 3.12 |
| Node.js 18 或以上 | 项目的协议流程会调用 Node 执行脚本；建议安装仍受支持的 LTS 版本 |
| 一个你能正常收信的邮箱 | 用于首次注册与手动读取验证码；试跑注册流程请使用尚未注册的地址 |
| 可访问相关服务的网络 | 包括注册网站、邮箱服务和首次下载浏览器所需的网络 |

Python 与 Node.js 可从 [Python 官网](https://www.python.org/downloads/) 和 [Node.js 官网](https://nodejs.org/) 安装。Windows 安装 Python 时，勾选加入 PATH 的选项；安装完成后重新打开终端。

下面两套命令按自己的系统选一套。命令要逐行执行，上一步没有报错再继续；不要复制代码框外面的说明文字。

### 3.2 Windows：安装项目依赖

在项目文件夹中打开 PowerShell。也可以使用下面的命令进入目录；如果你解压在别处，请替换路径。

```powershell
Set-Location "C:\code\turb-gpt-free-register"
python --version
node --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`.venv` 是这个项目自己的 Python 环境。后续明确使用其中的 `python.exe`，就不需要额外执行“激活环境”，也能减少装错依赖的问题。

如果 `python` 找不到，而电脑已安装 Python，可以先运行 `py -3 --version`；能显示合适版本时，将上面的 `python -m venv .venv` 换成 `py -3 -m venv .venv`。如果两种命令都找不到，先检查 Python 安装和 PATH。

### 3.3 macOS / Linux：安装项目依赖

先在终端进入你保存项目的目录，再执行：

```bash
python3 --version
node --version
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
```

如果 Linux 提示缺少 `venv`，先按当前发行版的提示安装对应 Python 的 venv 组件。以下可见窗口模式需要桌面环境；无桌面服务器需要另行选择无头模式或云浏览器，并满足相应浏览器的运行依赖。

### 3.4 新建自己的 `.env` 配置

在项目根目录新建一个 UTF-8 文本文件，名称必须是 **`.env`**。Windows 记事本“另存为”时选择“所有文件”，避免保存成 `.env.txt`。已有 `.env` 的用户只需核对并修改对应项，不要覆盖其他配置。

复制以下内容，并把前两项换成自己的值：

```dotenv
# 本地管理页面的登录密码：自己设置一段不易猜到的字符串
WEBUI_AUTH_CODE="请替换成你自己的长授权码"

# 一个你能收信、准备用来注册的邮箱
REGISTER_EMAIL="you@example.com"

# 第一次先在本机显示浏览器窗口，方便观察
REGISTRATION_DRIVER="cloak"
CLOAK_HEADLESS="False"
BROWSER_DATA_SAVER_MODE="False"

# 自己去邮箱看验证码，不需要导入邮箱池
USE_EMAIL_SERVICE="False"
OTP_MAX_WAIT="180"

# 第一次只做注册，之后再按需打开附加功能
ENABLE_CODEX_AUTO="False"
ENABLE_2FA="False"
ENABLE_FLOW_TRIGGER="False"
AUTO_PLAN_CHECK_AFTER_REGISTER="False"
SUB2API_AUTO_EXPORT="False"

# 当前先不指定项目代理；下一小节说明如何填写
PROXY_POOL="[]"
CLOAK_USE_PROXY="True"
PROXY_POOL_UPSTREAM_PROXY=""
PLAN_CHECK_UPSTREAM_PROXY=""
```

这里的 `True` 表示开启，`False` 表示关闭。显示名留空时，WebUI 注册任务会自动生成。

**不要把 `.env.example` 原样复制后就直接开始注册。** 它是一份配置参考，其中包含示例登录码、具体 Roxy 团队/项目 ID，并启用了自动邮箱、2FA、Flow 等配置。它和 `config/` 中的源码默认值也不完全一致。上面的配置是本教程专门选择的一组起步值。

如果你已经复制了模板：除了核对以上项目，还要替换模板的 `WEBUI_AUTH_CODE`，并清空或重新设置 `WEBUI_SESSION_SECRET`。新建最小配置时可以不写 `WEBUI_SESSION_SECRET`，程序会处理默认签名密钥。

### 3.5 根据你的实际网络配置代理

如果你的网络可以直接访问所需服务，保留 `PROXY_POOL="[]"` 即可。

如果需要让项目连接本机已启动的代理软件，查看该软件提供的 **HTTP 代理端口**，再修改 `.env`。例如，只有当你的 HTTP 代理确实监听在 `127.0.0.1:7897` 时，才使用：

```dotenv
PROXY_POOL='["http://127.0.0.1:7897"]'
CLOAK_USE_PROXY="True"
```

`127.0.0.1` 表示当前运行程序的电脑，`7897` 只是端口示例，并非所有代理软件的默认端口。代理的软件名称、订阅链接或网页管理地址都不能直接当代理 URL 填进去。

在 WebUI 的「代理」相关配置中，代理池按一行一个地址填写，例如 `http://主机:端口`。带认证的代理通常是 `http://用户名:密码@主机:端口`，具体以服务商给出的信息为准。

两个容易忽略的细节：

- Cloak 只有在 `CLOAK_USE_PROXY=True` 时才会使用项目传入的代理；模板里的这一项是 `False`，只填代理池还不够。
- `PROXY_POOL_UPSTREAM_PROXY` 和 `PLAN_CHECK_UPSTREAM_PROXY` 用于额外的代理链。普通单层代理先留空。浏览器能打开网站也不一定代表 Python 请求、邮箱收件走了同一条网络路径。

### 3.6 启动本地网页

Windows：

```powershell
.\.venv\Scripts\python.exe web.py --open-browser
```

macOS / Linux：

```bash
.venv/bin/python web.py --open-browser
```

正常启动后会显示本地地址，并尝试自动打开浏览器。没有自动打开时，手动访问：

[http://127.0.0.1:5000](http://127.0.0.1:5000)

在登录页输入刚才设置的 `WEBUI_AUTH_CODE`，不需要填写 ChatGPT 用户名或密码。如果没有配置授权码，启动日志会显示本次生成的临时授权码。

**先不要关闭启动程序的终端。** 前台运行时，程序需要持续运行才能提供网页和执行任务。打开网页成功只代表控制台已经运行，尚未完成账号注册。

### 3.7 在网页里提交第一个任务

1. 打开「配置」，确认注册驱动为 `cloak`、「Cloak无头」已关闭。
2. 在「邮箱 / OTP」中确认「自动取邮箱+收码」已关闭，「手动注册邮箱」是自己的地址；如有修改，点击「保存」并等待生效提示。
3. 打开「注册」，将 **数量设为 1、线程设为 1**。页面线程初始值可能是 3，需要手动调整。
4. 点击「开始注册」。首次使用 Cloak 时可能需要下载浏览器组件，留意终端和任务日志。
5. 点击任务旁的日志图标，观察进度；等日志提示需要邮箱验证码后，再去邮箱收件箱或垃圾邮件里找最新的验证码。
6. 如果启动 WebUI 的终端出现 `>>> 手动输入……的邮箱验证码`，直接在该终端输入验证码并回车。否则，在网页任务旁的「邮箱验证码」框输入，并点击勾选按钮提交。
7. 等待任务完成，到「账号」页查看结果。

当前实现有一个需要知道的交互细节：**前台终端也可能进入验证码输入等待。** 如果你已经在网页提交，流程仍停着，而终端正显示输入提示，请在等待期限内回终端按一次回车，让它继续读取网页提交的验证码。不要在两个地方重复提交同一个验证码。超时并重发后，使用新邮件中的验证码。

验证码输入框出现，并不一定表示程序已经走到收码步骤，以日志提示为准。手动模式在 WebUI 中每次只允许一个注册任务；想处理多个邮箱，请看第 5 节。

### 3.8 怎样确认成功

可以依次检查：

- 「注册」页的任务显示成功，日志中已经取得 `accessToken` 并保存账号。
- 「账号」页能找到对应邮箱；本教程的实际注册任务应有 Token，而不只是一个导入的空账号记录。
- 在账号行的更多操作中，可以选择「复制登录凭据」，查看已保存的邮箱、注册密码及可用的 2FA 信息。

新流程需要密码时，程序通常会生成注册密码。**ChatGPT 注册密码与邮箱本身的密码是两回事**，不要把导入邮箱时的邮箱密码当成 ChatGPT 密码；没有保存的字段也不会自动补出来。

本教程关闭了 Codex 自动授权，因此 Codex 显示“跳过”是预期结果。如果之后打开授权，出现“部分成功”，应分别查看账号是否已创建、Codex 是否失败，通常不需要重新注册同一邮箱。

### 3.9 关闭与下次启动

等任务结束后，在启动程序的终端按 `Ctrl+C` 关闭服务。下次进入项目目录，直接执行第 3.6 节的启动命令；不用每次重建虚拟环境或重新安装依赖。

关闭浏览器标签页不会可靠地停止后台任务；需要停止任务时使用页面对应的停止操作。

## 5. 跑通后，再启用自动邮箱与批量任务

### 5.1 先选择一种邮箱来源

自动模式需要让程序知道两件事：**从哪里拿邮箱、怎样读到验证码。** 只有邮箱地址通常不够。

| `EMAIL_SOURCE` | 来源 | 需要准备 |
| --- | --- | --- |
| `outlook` | Outlook 邮箱池 | 邮箱、邮箱密码、`clientId`、`refreshToken` |
| `generic_api` | 通用 API 邮箱池 | 邮箱地址，以及能取到该邮箱验证码的 API 地址 |
| `imap` | 通用 IMAP 邮箱池 | 邮箱、IMAP 密码或授权码，以及 IMAP 服务器、端口、SSL 设置 |
| `cloudflare_domain` | 域名邮件转发到 QQ | 自己的域名、Cloudflare Email Routing、QQ 邮箱和 QQ IMAP 授权码 |
| `cloudflare` | Cloudflare Worker 临时邮箱 | Worker API 地址、域名及对应的鉴权配置 |
| `gptmail` | GPTMail | 自己的 API Key |
| `mailnest` | MailNest | API Key、项目代码 |
| `cloudmail` | CloudMail | 自己的服务地址、Token 或生成 Token 所需的管理员登录信息、域名 |
| `remail` | Remail | API Key、项目 ID、邮箱后缀和订单模式，以及可用库存 / 余额 |
| `xigua` | 西瓜邮箱服务 | API Key、项目和 Offer 配置 |

`cloudflare` 和 `cloudflare_domain` 是两种不同方案：前者调用 Worker API，后者通过 QQ IMAP 收转发邮件，配置不能混用。QQ IMAP 要填授权码，不是 QQ 登录密码。

服务型来源通常在任务运行时申请邮箱，不要求像 Outlook 那样提前导入列表。具体字段可在「配置 → 邮箱 / OTP」中查看；需要完整参数时再对照 `.env.example` 和 `config/email.py`。

### 5.2 使用已有邮箱池

在「邮箱池」点击导入，选择与你的素材匹配的类型。每行一个邮箱，最常用的格式如下：

Outlook：

```text
you@outlook.com----邮箱密码----clientId----refreshToken
```

通用 API：

```text
you@example.com----https://mail.example.com/your-code-endpoint
```

这里的取码地址由你的邮箱服务提供，不是网页邮箱首页；上面的域名仅用于说明格式。

通用 IMAP：

```text
you@example.com----IMAP密码或授权码
```

IMAP 导入时还要填写统一的服务器、端口和 SSL。常见是 `993` 加 SSL，但应以邮箱服务商说明为准。

**准备用来注册的新邮箱，不要勾选「导入后默认视为注册成功账号」。** 该选项只是把你已有的账号记录导入管理页面，并把邮箱池标记为已用；它不会实际替邮箱注册账号，也不等于已经取得 Token。只有导入真实的已有账号时才使用。

导入后，到配置中设置，例如使用 IMAP：

```dotenv
USE_EMAIL_SERVICE="True"
REGISTER_EMAIL=""
EMAIL_SOURCE="imap"
```

务必清空之前手动试跑使用的固定邮箱。选择的来源应与导入类型一致，并确认池内有“可用”的邮箱。

支持多个来源，例如 `EMAIL_SOURCE="outlook,imap"`，表示领取失败时按顺序尝试下一个来源。第一次建议只选已经配好的一个来源，方便定位错误。

### 5.3 再逐步增加数量

先在自动模式下用 **数量 1、线程 1** 验证自动收码能成功，再按邮箱数量、机器性能和服务限额增加并发。

数量是任务次数，不是承诺成功的账号数。线程数变更影响新提交的批次；旧批次中已经运行或排队的任务仍会继续，不会因为改小了线程数就立刻停掉。

## 6. 注册驱动怎么选

当前代码支持以下五种方式：

| 驱动值 | 怎么运行 | 额外前提 |
| --- | --- | --- |
| `cloak` | 在本机运行 CloakBrowser，由程序控制浏览器页面 | 安装项目依赖，首次下载浏览器组件；可见窗口需要桌面环境 |
| `roxy` | 控制你本机的 RoxyBrowser | 单独安装并启动 Roxy，配置 API 地址、Token、自己的团队 / 项目 |
| `browser_use` | 控制 Browser Use 云端浏览器 | API Key、可用服务额度；网络和代理按云服务配置 |
| `skyvern` | 使用 Skyvern Browser Session | API Key、服务地址及对应的 Session 配置 |
| `protocol` | 通过 Python 直接发送协议请求 | 可用网络、Node.js；对服务端流程变化较敏感，排查需要更多技术背景 |

在「配置 → 注册方式」修改 `REGISTRATION_DRIVER`。仓库默认选择 Roxy，所以直接下载启动并不代表已经具备 Roxy 环境；本教程是主动改成 Cloak。

使用 Roxy 时，API 地址必须以你本机 Roxy 的实际设置为准。模板里写的是端口 `50000`，源码默认是 `50100`，不能只照抄其中一个；团队 / 项目也要获取并保存自己的值。

云浏览器运行在远端，不能把本机 `127.0.0.1` 当作远端可以访问的代理服务。当前本地浏览器流量统计与省流量模式主要用于 Roxy / Cloak，也不要把这些配置直接套到云浏览器上。

## 7. 需要 Codex 授权时再配置

### 7.1 自动授权与单独补跑

- **注册后自动授权：** 设置 `ENABLE_CODEX_AUTO="True"`，新注册流程会继续尝试授权。
- **已有账号补跑：** 在「账号」页选择账号，点击「补跑 Codex」或批量「补跑」。手动补跑可以在自动授权开关关闭时执行。

先完成一个账号的补跑，再考虑打开自动授权，更容易区分注册问题与授权问题。补跑可能涉及邮箱 OTP、密码、2FA 或手机验证，具体由服务端返回的流程决定，不能保证每次都只消耗一次验证码或一个号码。

沿用第 3 节的手动邮箱模式时，请保持前台终端运行，并先只补跑一个账号；收到终端验证码提示后在那里输入。**账号页的补跑不会自动新增注册任务，也不会自动出现注册页的验证码输入框。** 后台运行或批量补跑前，应先为已有账号配置能够自动收码的邮箱来源和收件凭据。

### 7.2 授权驱动与授权地址来源是两个设置

`CODEX_OAUTH_DRIVER` 决定如何执行授权。可选 `protocol`、`roxy`、`cloak`、`browser_use`、`skyvern`，或 `same_as_registration`。使用本教程的 Cloak 注册方案时，单独补跑可以选择 `cloak` 或 `same_as_registration`。

当前 Roxy / Cloak 的注册后自动授权会复用当次浏览器窗口。它们和单独补跑的驱动调度存在区别，不要认为修改 `CODEX_OAUTH_DRIVER` 就一定会改变正在运行的注册流程。

`CODEX_AUTH_URL_SOURCE` 决定授权链接由谁生成、结果交给谁：

| 值 | 意义 | 需要准备 |
| --- | --- | --- |
| `local` | 本项目生成授权链接并交换 Token | 可用账号、收码和网络条件 |
| `cpa` | 从 CPA 获取授权链接并提交回调 | 自己运行的 CPA 服务、`CPA_MANAGEMENT_URL`、`CPA_MANAGEMENT_KEY` |
| `sub2` | 从 sub2 获取授权链接并回传结果 | 自己的 sub2api 服务及 `config/sub2api.py` 对应设置 |

CPA 指 CLIProxyAPI 相关管理服务；CPA 和 sub2api 都是需要另外准备的外部服务，不会随着本项目启动而自动安装。

例如，在单独补跑前，可以明确设置：

```dotenv
CODEX_OAUTH_DRIVER="same_as_registration"
CODEX_AUTH_URL_SOURCE="local"
```

这两行只选择授权方式，不会替你补齐邮箱收件或手机验证条件。源码的授权地址来源默认是 `cpa`，而 `.env.example` 写的是 `local`，建议自己明确选择。

### 7.3 如果出现手机验证

当前代码接入了 `grizzly`、`smsbower`、`l`、`h` 等短信服务方式。对应服务需要自己的密钥、项目 / 服务代码、国家等配置；本地 L 服务的接口说明在 `L_API.md`。

手机验证仅在流程要求时执行。短信价格、库存、有效时间和重试消耗以提供服务的平台为准；没有配置时，账号注册可能已成功，但授权会停在需要手机验证的步骤。普通注册试跑无需先购买短信服务。

### 7.4 到哪里找授权结果

在「Codex 授权」页查看、下载。业务数据主要保存在 `turb.sqlite3`，日志中的 `sqlite://codex_accounts/...` 表示数据库中的记录，不是让你去磁盘上找同名文件夹。

CPA / sub2 模式可能只在本地保存“回调已提交”的回执。如果下载内容的类型是 `codex_cpa_callback` 或 `codex_sub2_callback`，它不等于完整 Token 凭证；应到相应服务确认授权结果，或使用页面中可用的“从 CPA 下载”功能。

普通账号的 AT、Codex OAuth 凭证、Codex Agent 凭证有不同用途，导出后需按照接收程序支持的格式使用。

## 8. 不用网页，也可以用命令行

以下示例为 Windows，macOS / Linux 把 `.\.venv\Scripts\python.exe` 替换为 `.venv/bin/python`。仍然需要先完成 `.env`、网络和邮箱配置。

注册一个账号：

```powershell
.\.venv\Scripts\python.exe main.py
```

沿用手动邮箱配置时，终端还会要求输入显示名称，例如 `Alex Chen`，不要直接留空回车；后续邮箱验证码也在终端输入。这里与 WebUI 自动生成显示名的行为不同。

查看详细步骤：

```powershell
.\.venv\Scripts\python.exe main.py -n 1 --verbose
```

自动邮箱模式配置好后，提交 3 个任务、1 个线程：

```powershell
.\.venv\Scripts\python.exe main.py -n 3 --workers 1 --continue-on-fail
```

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `-n` / `--count` | 本次注册任务数量 | `1` |
| `--workers` | 并发线程数；多线程要求启用自动邮箱 | `1` |
| `--delay` | 串行时为任务之间的等待秒数；并发时为提交任务的错峰间隔 | `0` |
| `--continue-on-fail` | 某次失败后继续后续任务；已经运行的任务不会因此回滚 | 未开启 |
| `--verbose` | 输出详细步骤和错误信息 | 未开启 |

WebUI 也可以换端口：

```powershell
.\.venv\Scripts\python.exe web.py --port 8000 --open-browser
```

此时访问 [http://127.0.0.1:8000](http://127.0.0.1:8000)。默认监听 `127.0.0.1`，只有本机能访问；`--host 0.0.0.0` 会扩大访问范围，新手一般无需修改。

macOS / Linux 还可使用仓库的后台管理脚本：

```bash
bash webui.sh start
bash webui.sh status
bash webui.sh logs
bash webui.sh stop
```

这是四个不同操作，按需要执行；`logs` 会持续显示日志。脚本优先使用 `.venv/bin/python`，日志在 `logs/webui.log`，进程记录在 `run/webui.pid`。不要同时用前台命令和脚本启动相同端口。

## 9. 配置和数据保存在什么地方

### 配置怎样生效

- `config/*.py` 提供源码默认值；日常通过 `.env` 或 WebUI 修改配置即可。
- WebUI 可编辑项保存到项目根目录 `.env`，不会回写 `config/*.py`。
- 启动时已有系统环境变量通常优先于 `.env`；WebUI 保存 / 热加载时会重新读取 `.env` 并覆盖当前进程的对应变量。
- 多数任务配置可在保存后供后续任务使用；授权码、Session 密钥和部分后台线程池设置需要重启，正在执行的任务也未必会切换到新值。
- 手动用编辑器修改 `.env` 后，最简单可靠的做法是等任务结束，再重启 WebUI。
- 大多数配置填空表示回到源码默认值，不表示关闭。开关请明确写 `False`；代理池可以用 `[]` 明确清空。

### 哪些文件需要保留

| 文件或目录 | 内容 |
| --- | --- |
| `.env` | 你自己的配置、服务密钥和 WebUI 授权码 |
| `turb.sqlite3` | 账号、邮箱池、任务、Codex OAuth 与 Agent 凭证等主要业务数据 |
| `turb.sqlite3-wal` / `turb.sqlite3-shm` | SQLite 运行期间可能出现的辅助文件 |
| `注册日志/` | 注册、授权补跑及其他后台操作的日志 |
| `logs/`、`run/` | 使用 `webui.sh` 时的服务日志与运行记录 |
| `sub2api.json` 或自定义输出路径 | 启用 sub2api 的 `file` / `both` 同步模式时可能生成的文件 |
| `.venv/` | 项目依赖环境，不是账号数据 |

旧版的邮箱 / 账号 JSON、TXT 和 Codex 文件会在迁移逻辑中被读入数据库。当前日常管理应通过 WebUI 和 SQLite，不要期待旧的 `注册成功的token.txt` 一直自动更新，也不要靠反复改旧 TXT 导入新邮箱。

### 最简单的备份办法

1. 等任务结束，停止 WebUI、CLI 及其他访问该数据库的进程。
2. 复制 `turb.sqlite3`；同目录若仍有对应的 `-wal`、`-shm` 文件，一起保存。
3. 另存 `.env`、需要保留的 `注册日志/` 和手动导出的凭证文件。
4. 恢复时先停止程序，再把对应数据放回同一版本或兼容版本的项目目录。

数据库使用 WAL 模式，不建议运行中只复制 `turb.sqlite3` 主文件。数据库、日志、配置和导出文件都可能含密码或 Token，备份时应一并妥善保管。`.gitignore` 是提交时的忽略规则，不是加密功能。

## 10. 常见问题：先查哪里

| 现象 | 优先检查 |
| --- | --- |
| 找不到 `python`、`node` 命令 | 是否安装、是否加入 PATH；安装后重新打开终端 |
| `No module named flask` / `cloakbrowser` | 是否使用项目的虚拟环境；重新用同一个环境的 Python 安装 `requirements.txt` |
| 找不到 `web.py` / `requirements.txt` | 当前终端是否位于项目根目录 |
| 网页打不开或端口占用 | 看启动终端是否报错；检查旧实例，或用 `--port 8000` |
| 不知道 WebUI 登录码 | 看 `.env` 的 `WEBUI_AUTH_CODE`；未配置时看启动日志里的临时授权码 |
| 明明改了登录码却不生效 | 保存后重启 WebUI；检查是否通过启动参数或系统环境变量另设了授权码 |
| 连接 `127.0.0.1:7897` 被拒绝 | 代理程序是否运行、实际端口和协议是否匹配；不需要代理时明确清空代理池 |
| Cloak 下载失败或无法启动 | 查看下载网络、浏览器组件对系统的支持及依赖错误；先保留完整错误信息 |
| 填了代理但 Cloak 没使用 | 检查 `CLOAK_USE_PROXY=True`；不要只改代理池 |
| Roxy 提示 API / 团队 / 项目错误 | 确认 Roxy 已运行，API 地址、Token、团队和项目均来自你自己的环境 |
| “手动模式未配置 REGISTER_EMAIL” | 填写「手动注册邮箱」，或正确启用自动邮箱模式 |
| “所有邮箱来源均领取失败” / 邮箱池为空 | 来源是否选对、是否有可用邮箱；服务型邮箱检查密钥、项目、余额及库存 |
| 邮箱里有验证码但任务不继续 | 确认是当前任务的新验证码；手动模式还要检查终端是否正在等输入 |
| 等验证码超时 | 检查垃圾邮件、收件凭据和网络，适当增加 `OTP_MAX_WAIT`；重发后使用最新验证码 |
| 自动模式还反复使用同一个邮箱 | 清空试跑时的 `REGISTER_EMAIL`，确认自动领取已开启 |
| 注册成功，Codex 却失败 | 在账号页看授权错误，补齐所需配置后只补跑 Codex |
| 查活失败 | 先看具体错误；网络或邮箱故障也会导致查活失败，不能只凭这三个字认定账号失效 |
| 找不到旧说明里的 Token 文本文件 | 查看「账号」「Codex 授权」页面；当前主要业务数据在 `turb.sqlite3` |
| 页面变化、403、找不到输入框 | 查看失败步骤和当前服务返回内容；检查网络及驱动兼容性，不要仅靠增加线程反复重试 |

排查时先保留 **任务编号、使用的驱动、邮箱来源和失败步骤附近的日志**。对外分享前遮住邮箱凭据、验证码、代理密码、Cookie、Token 和 API Key。

## 11. 进阶功能：需要时再看

| 功能 | 作用与前提 |
| --- | --- |
| 2FA | 为账号设置动态口令，涉及重新验证和密钥保存；不同驱动的注册阶段支持有差异，不能只凭开关开启就认定设置成功 |
| 查活刷新 AT | 尝试重新登录并刷新账号凭证，需要账号及可用验证条件 |
| 套餐 / Plus 试用资格查询 | 查询服务端返回的状态，不会自动开通套餐 |
| 换绑邮箱 | 从指定来源取得新邮箱并更换绑定，需要相关验证条件 |
| 提链 | 调用额外服务获取支付 / 试用相关链接，需要服务地址与 CDK；不等于已经获得 Plus |
| Codex Agent | 另一套 Agent 凭证生成流程，与常规 Codex OAuth 分开理解 |
| CPA / sub2api | 把授权流程或凭证对接到你配置的外部管理服务 |
| Flow | 注册后的可选外部回调，会向配置的接口发送账号 Token |
| 浏览器流量与省流量模式 | Roxy / Cloak 可统计或减少部分资源流量；首次跑通前建议保留简单配置 |

提链、Flow、凭证同步等功能会把账号 Token 或凭证发送给所配置的服务，使用前确认目标服务由你信任和管理。
